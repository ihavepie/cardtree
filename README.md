# 书签板（cardtree）

一个 Chrome / Edge 浏览器扩展（Manifest V3）：**把新标签页变成「书签板」书签管理器**。
仿照 [CardTree Bookmarks](https://chromewebstore.google.com/detail/cardtree-bookmarks/ecdimagmnlbhoekbhhkdfhgenhpmbhkf) 的卡片树布局，浅色玻璃拟态视觉，重点打磨了**拖拽整理**体验。

技术栈：**Vite + Vue 3**（Composition API），拖拽基于原生 HTML5 Drag & Drop，零额外拖拽库。

## ✨ 功能

- 🏠 **新标签页即桌面**：`chrome_url_overrides.newtab`，打开新标签页直接进入
- 🗂️ **卡片树级联布局**：以「书签栏」为唯一顶层（其他书签/移动设备书签的内容自动平铺进书签栏），子文件夹以「标题 + 树线」扁平嵌套（**首次默认折叠**、点开才展开），仅最外层为毛玻璃面板、内层不叠卡片，亚克力通透
- 🧱 **文件夹排列可切换**：顶栏布局按钮单击即可在「文件夹纵排（一条条往下堆）」与「文件夹并排（栏数按窗口宽度自动）」之间切换；网址（书签）始终保持横排并排，选择持久化
- 📐 **前 N 个 + 展开全部**：每个文件夹的直接书签默认只显示前 8 个，其余收成一条「展开全部 N 个」，卡片高度基本恒定；展开状态按文件夹记住
- 🔽 **一键折叠/展开**：顶栏按钮一键折叠或展开所有子文件夹
- 🧭 **侧边栏文件夹树**：左侧可折叠的文件夹导航，**单击 = 选中 + 定位 + 展开/收缩**（三合一）、**点箭头单独展开/收缩**（与主区卡片双向同步）；右键文件夹可收缩/展开、新建书签/子文件夹、重命名、移动、删除整个文件夹；支持把主区书签/文件夹**拖入侧边栏文件夹**完成移动（顶栏 ☰ 可收起侧边栏）
  - **拖拽投放反馈**：一开始拖，整栏进入投放态（**两张卡都亮成投放区** + 顶栏文案变「移入文件夹」+ 「松手移入 N 项」提示条）；悬停的文件夹行高亮为落点；拖文件夹到它自己/后代时整行变灰（`.drop-invalid`）并拒绝落点。侧栏行的悬停展开阈值从 600ms 收紧到 **320ms**（行窄，等 600ms 手感发黏）
  - **侧栏收起时也能拖进去**：拖拽中把鼠标贴到窗口左边缘（≤12px）停 **200ms**，侧栏临时滑出；真的用它投放了就留着，只是路过则还原你原本的设置（不偷偷改偏好）
  - **拖拽期间侧栏整棵树临时展开**（`store.dragExpandAll`）：否则悬停某行的自动展开会把下面的行推走，你要投的那一行会在等待中漂移；拖完恢复各自的折叠状态
  - **hover 快捷动作**：悬停文件夹行时右侧浮出「＋（在此新建书签）」「⋯（重命名/移动/删除）」；不占位、不改变行高（计数胶囊淡出而不塌陷），拖拽中自动让位回计数
- 🎨 **自定义背景**：内置多套渐变/壁纸预设 + 本地上传图片 + 一键随机切换，持久化保存
- 🗂️ **工作区（一键打开一组）**：侧栏顶部把常一起打开的网站攒成一组
  - **点一行 = 展开**，逐个列出组内的每个标签页（`▾ 开始工作 3` → YouTube / Notion / GitHub）；**点其中某一个 = 只开这一个**（后台标签），悬停「✕」从组里移除（不动书签）
  - **打开整组**：悬停行时浮出的第一个按钮「⧉」，或「⋯ → 立即打开全部」—— 走后台标签并给一条带「撤销」的提示（撤销关掉刚开的那些标签）
  - hover 的「＋」把当前选中的书签加进来（加完自动展开让你确认）；「⋯」（右键同款）：立即打开全部 / 展开·收起标签页 / 重命名 / 删除
  - **把书签/文件夹直接拖到工作区行上 = 加进这一组**：悬停该行 → 行高亮成落点 + 表头提示「松手加进 N 项」，松手后自动展开把新条目列出来。语义是**登记不是移动** —— 工作区只是"我要开的这几个站"的清单，书签本体留在原文件夹里（所以两张卡的拖拽语义不同：文件夹卡 = 移进去，工作区卡 = 加进清单）。拖文件夹进来会递归收集里面的书签，和选中文件夹点「＋」完全一致；两条路径共用 `store.addNodesToWorkspace()` 与同一套反馈文案。回归 `test/sidebar-drop-check.mjs` 的 D6/D7
  - 头部「＋ 新建」可用选中项直接建组（按钮做成**白色小按钮**：`--btn-ghost-white`（浅色近白 0.72 / 深色一枚 0.14 的浅色玻璃片）+ 深色字，**没有边框线**（靠一层浅投影托起来），不再是几乎看不见的透明文字按钮）。组里条目存 `{ id, title, url }`，`title/url` 是**快照兜底**：
    渲染与打开优先用 `id` 取书签的**当前值** ——
    - **书签改名/改网址会跟着变**（以前只存快照、把 `n.id` 丢掉了，所以永远是旧标题）
    - **书签被删则退回快照**并标「已删除」徽标，工作区不散架（这是当初存快照的初衷）
    - 快照在每次 `load()` 后刷新，所以"改名后又删掉"显示的也是**最后知道的名字**，不是最初的旧名
    - 老数据（只有快照没有 id）在启动时按 url 反查一次补上 id
  - **选中文件夹也能加进工作区**：递归收集里面的书签。以前只收 `n.url` 的节点、而
    `topLevelSelection()` 又排除文件夹的后代 —— 选一个装着 8 个书签的文件夹会得到"没选中书签"
  - **建组与"加入选中项"共用同一条去重逻辑**（原来建组不去重、加组才去重）
  - **打开结果如实反馈**：全部失败 → "都没打开成功"；部分失败 → "打开了 M/N 个（K 个失败）"；
    只有真的开了才给「撤销」
  - **零新增权限**：`chrome.tabs.create / remove` 属基础能力，不需要 `tabs` 权限（那权限是为了读 url/title 这类敏感字段）；非扩展环境回退 `window.open`
- 🧱 **侧栏拆成上下两张并列的玻璃卡片**：上面「工作区」卡（我要打开的）、下面「文件夹」卡（我要整理的）。
  `.sidebar` 退化成纯粹的**列容器**（自己不再是卡片），所以不存在卡片套卡片；两张卡各自有圆角、
  边框、毛玻璃与阴影，中间留 12px 间距；各自有独立滚动条。
  - **缝里不铺任何东西**（试过填一层同样的玻璃，会把两张卡焊成一根柱子，观感更差 —— 已回退）。
    缝里露出的就是页面背景，靠三件事让它读起来干净：
    ① 卡片有**玻璃边**（`--card-border`，浅色近白 / 深色 `rgba(255,255,255,.07)`）→ 轮廓立起来；
    ② `--card-shadow` 足迹收一点（`0 10px 26px -12px`）→ 别让上下两张卡的投影在十几 px 的缝里叠两层；
    ③ **浅色底整体抬亮**（见下面浅色那节）→ 底色越接近卡片，缝越不像"脏印子"。
  - **卡片不支持折叠**（曾经的"点标题栏收起"已整体移除）：折叠后分隔条没有高度可分配，
    会变成"拖了没反应"。要缩小某张卡就拖分隔条（15%~80%），要不占地方就把它的内容清空/收起内部项
  - 上面那张卡的高度**就是**分隔条定的固定高度（`flex: 0 0 <split>%`），下面那张吃掉剩余，
    底边与主区卡片齐平
- 🎨 **浅色 / 深色各走一套底子**（这一轮分开调的）
  - **浅色**：页面底抬亮、少灰（`#f3f6fa → #fafcfe → #f0f4f8`，环境光透明度 0.16/0.2 → 0.10/0.14）；
    噪点 `opacity` 0.035 → **0.022**（噪点叠在缝里会加重"脏"感）；卡片 `--card-bg` 0.2 → **0.26**、
    加 `--card-border: rgba(255,255,255,.5)` 的玻璃边
  - **深色**：卡片 `rgba(30,41,59,.5)` → **`rgba(38,50,69,.55)`**（亮一档，和近黑底的层次更清楚）；
    卡片边 `rgba(255,255,255,.07)`；三级文字 `--text-3` `#64748b` → **`#7b8a9e`**（计数/提示原来偏暗）；
    页面底两端压深（`#0e1626 → #0d131c`），卡片更"浮"得起来
  - 取证脚本：`test/panel-seam-shot.mjs`（4 倍放大截"两卡之间那道缝"与卡片圆角，深浅各一套）
- 🧩 **四张卡片共用同一条玻璃边**：侧栏「工作区」/「文件夹」、顶部**看板索引条**、主卡片 ——
  都是同一套配方（`--card-bg` + `backdrop-filter` + `--card-shadow`）**外加 `--card-border`**
  （浅色 `rgba(255,255,255,.5)` / 深色 `rgba(255,255,255,.07)`）。看板索引条原来漏了这条边，
  于是四张卡里只有它没轮廓（用户一眼看出来的那个"边框线"问题）。
  回归 `test/card-surface-check.mjs`：自动找出所有"卡片面"（圆角 ≥9 + 有底色 + 有投影 + 够大），
  逐个断言**必须带边**，并检查这四张卡都在场；附带存 `card-surfaces-{light,dark}.png` 同框截图。
  （索引条圆角仍是 9px，比卡片的 14px 小一档 —— 这是"工具条 vs 内容卡片"的刻意区分。）
- 🪟 **侧边栏可拖动**（列内布局 + 宽度）
  - 三个拖动区互不重叠，都做成"鼠标移上去才浮出小把手"：**卡片顶部拖拽条**（换位）、
    **两卡之间的分隔条**（调高度）、**侧栏右边缘**（调宽度）
  - **拖拽条换位**：每张卡**顶部有一条 13px 的专用拖拽条**（就是照「拖右边缘调宽度」那根做的：
    独立元素 + `mousedown` + 窗口级 `mousemove`）。鼠标移上去时**只在抓手周围浮出一颗小胶囊**
    （不再给整条 200px 的底色 —— 那看着像一行可点内容），按住拖到另一张卡的上方/下方即换位；
    **标题栏也照样能拖**（卡片已不支持折叠，所以点击和拖动不冲突）。
    拖动中会有一个跟着鼠标的深色小药丸（写着卡片名），落点卡整张描边、那条边再画一条强调横线
  - ⚠️ 换位走的是**指针事件**（`mousedown`/`mousemove`/`mouseup`），**刻意不用原生 HTML5 拖拽**：
    后者是否肯启动取决于浏览器环境，在扩展里会静默失败（连 `dragstart` 都不一定来），
    而且它对"落点在子元素上"极敏感。指针事件完全可控，和「拖宽度」「拖分隔条」是同一套机制；
    拖动超过 4px 才算拖拽（不影响点击折叠），松手后那一次 `click` 会被吞掉（否则会顺手把卡片折叠）
  - **拖中间的分隔条调高度**：两张卡之间那条 12px 间距就是分隔条，鼠标移上去浮出一颗小把手、
    光标变 `row-resize`；上下拖 = 改上面那张卡的**固定高度**（占侧栏的 15%~80%），下面那张吃掉剩余
    - ⚠️ 这里曾经用 `max-height`（高度**上限**）而不是固定高度 —— 后果是：工作区列表短于上限时，
      拖分隔条**数据变了但像素不动**，用户只会觉得"拖不动"。已改为固定高度（就是 Unity / PS 那种
      分栏：你定多少就是多少）。回归见 `workspace-check` 的 `W13`（故意用**空工作区**去拖）
    - 上面那张卡内容少时会有空白，这是分栏布局的正常表现：把分隔条往上拖缩小它即可
  - **拖右边缘调宽度**：`.sidebar-resizer` 同样是"移上去浮出小把手"（平时隐形，hover 变灰、拖动变强调色并变长），
    和上面两个把手是同一套视觉语言。把手**视觉上落在"侧栏右边 ↔ 主卡片左边"这条缝的正中**、
    上下就是侧栏的垂直中心
  - 三个把手的**可见部分都保持"悬停才浮出"**；为了让它们好抓，只有一个**完全不可见的命中区**被放大：
    宽度手柄左右各溢出一截（`::before`，left -8px / right -26px，上下再各 10px）、
    高度分隔条上下各撑 6px（`::before`）—— 观感一点不变，但不用再瞄准那 6px / 14px
  - 顺序、高度、宽度都持久化（`cardtree:panelOrder` / `cardtree:panelSplit` / `cardtree:sidebarWidth`）

- 🎛️ **交互态手感**：侧栏行/按钮**去掉了按压缩放**（不再 `scale` 位移）；文件夹选中态 =
  **单纯一个淡色描边框**（中性冷灰 `rgba(100,116,139,.5)`，无底色、无左侧紫条、文字不出紫）；
  hover 的方向是"**往白里提亮**"（毛玻璃上的高光），不是压一层灰：
  `--hover-bg`（行/chip，浅色 `rgba(255,255,255,.5)` ／ 深色 `rgba(255,255,255,.075)`）、
  `--hover-bg-strong`（卡片/菜单项/按钮）、`--active-bg`（按下再白一档）、
  `--hover-fg`（悬停文字**变深/变亮**而不是变色相）、`--hover-border`；顶栏玻璃按钮另有
  `--btn-hover-bg` / `--btn-hover-border`（同样往白里走）。
  ⚠️ 例外：**近实底**的面板（右键菜单 / 详情抽屉 / 弹窗 / 便签 / 背景面板，底色 `--panel-bg` ≈ 0.94 白）
  上"白上加白"等于没有，所以另有一组 `--hover-bg-solid` / `-strong` / `--active-bg-solid`（压灰）。
  **主题色 `--accent` 走过三步：靛蓝（显紫）→ 中性石墨（没颜色）→ 现在的"钢蓝"**
  （浅色 `#3f7cae` ／ 深色 `#8ab8dd`，饱和度压到 ~40%）：和石板灰同族、看得出是主题色但不发紫。
  它用在选中框（`--sel-bg`）、落点环、焦点环（`--focus-ring`）、计数徽标、滚动联动条、图标底色、
  便签球、页面环境光与落点光晕上；
  回归 `test/no-purple-check.mjs`（计算样式转 HSL，扫色相 230°–305° 且饱和度 >15% 的，
  含阴影/边框/背景图，浅色 + 深色都要求 0 处），观感截图 `test/hover-shots.mjs`

## 🔎 改了代码但界面没变？

顶栏的版本号是**从 `chrome.runtime.getManifest()` 实时读的**（`TopBar.vue`）。所以：

- 顶栏显示 `v5.1` = 新构建已生效
- 还显示旧版本号 = 扩展没重载 → 去 `chrome://extensions` 点这个扩展的**刷新**按钮

扩展加载的是 `dist/`，浏览器**不会**自动重载已加载扩展的代码，每次 `npm run build` 后都要点一次刷新。

## ⚙️ 权限说明

- `bookmarks`：读取与增删改收藏夹（必须）
- `storage`：记住折叠状态、最近打开、回收站
- `favicon`：通过 `_favicon` 服务读取站点真实图标

## ⌨️ 快捷键

| 按键 | 动作 |
| --- | --- |
| 单击书签 | 选中（Ctrl/⌘ 多选，Shift 范围） |
| 双击书签 | 新标签页打开 |
| Enter | 打开选中项 |
| F2 | 重命名选中项 |
