## 视觉系统

### 四张卡片共用同一条玻璃边

侧栏「工作区」/「文件夹」、顶部**看板索引条**、主卡片 —— 都是同一套配方：
`--card-bg` + `backdrop-filter: blur(28px) saturate(1.9)` + `--card-shadow`，**外加 `--card-border`**
（浅色 `rgba(255,255,255,.5)` / 深色 `rgba(255,255,255,.07)`）。

看板索引条原来漏了这条边，于是四张卡里只有它没轮廓（用户一眼看出来的那个"边框线"问题）。

> 回归 `test/card-surface-check.mjs`：自动找出所有"卡片面"（圆角 ≥9 + 有底色 + 有投影 + 够大），
> 逐个断言**必须带边**，并检查这四张卡都在场；附带存 `card-surfaces-{light,dark}.png` 同框截图。

### 圆角分三档

容器 **9px**（索引条）→ 内层胶囊/条目 **6px** → 计数徽标全圆（小数字徽标保持胶囊形）。
主卡片是 **14px**，索引条用 9px 是刻意的 —— 区分"工具条"与"内容卡片"。

### 交互态：hover 是"往白里提亮"

侧栏行/按钮**去掉了按压缩放**（不再 `scale` 位移）；文件夹选中态 = **单纯一个淡色描边框**
（中性冷灰 `rgba(100,116,139,.5)`，无底色、无左侧紫条、文字不出紫）。

hover 的方向是"毛玻璃上的高光"，不是压一层灰：

| 变量 | 用途 | 取值 |
| --- | --- | --- |
| `--hover-bg` | 行 / chip | 浅色 `rgba(255,255,255,.5)` ／ 深色 `rgba(255,255,255,.075)` |
| `--hover-bg-strong` | 卡片 / 菜单项 / 按钮 | 更白一档 |
| `--active-bg` | 按下 | 再白一档 |
| `--hover-fg` | 悬停文字 | 变深/变亮，**不变色相** |
| `--btn-hover-bg` / `--btn-hover-border` | 顶栏玻璃按钮 | 同样往白里走 |

⚠️ 例外：**近实底**的面板（右键菜单 / 详情抽屉 / 弹窗 / 便签 / 背景面板，底色 `--panel-bg` ≈ 0.94 白）
上"白上加白"等于没有，所以另有一组 `--hover-bg-solid` / `-strong` / `--active-bg-solid`（压灰）。

### 主题色走过三步：靛蓝 → 石墨 → 钢蓝

靛蓝（显紫）→ 中性石墨（没颜色）→ 现在的**钢蓝**（浅色 `#3f7cae` ／ 深色 `#8ab8dd`，饱和度压到 ~40%）：
和石板灰同族、看得出是主题色但不发紫。

用在选中框（`--sel-bg`）、落点环、焦点环（`--focus-ring`）、计数徽标、滚动联动条、图标底色、
便签球、页面环境光与落点光晕上。

> 回归 `test/no-purple-check.mjs`：计算样式转 HSL，扫色相 230°–305° 且饱和度 >15% 的
> （含阴影/边框/背景图），浅色 + 深色都要求 **0 处**。观感截图 `test/hover-shots.mjs`。

### 浅色 / 深色各走一套底子

**浅色** —— 页面底抬亮、少灰：`#f3f6fa → #fafcfe → #f0f4f8`，环境光透明度 `0.16/0.2 → 0.10/0.14`。
噪点 `opacity` `0.035 → 0.022`（噪点叠在缝里会加重"脏"感）。
卡片 `--card-bg` `0.2 → 0.26`，加 `--card-border: rgba(255,255,255,.5)` 的玻璃边。

**深色** —— 卡片 `rgba(30,41,59,.5) → rgba(38,50,69,.55)`（亮一档，和近黑底的层次更清楚）；
卡片边 `rgba(255,255,255,.07)`；三级文字 `--text-3` `#64748b → #7b8a9e`（计数/提示原来偏暗）；
页面底两端压深（`#0e1626 → #0d131c`），卡片更"浮"得起来。

## 侧边栏

### 两张并列玻璃卡，缝里不铺东西

`.sidebar` 退化成纯粹的**列容器**（自己不再是卡片），所以不存在卡片套卡片；两张卡各自有圆角、
边框、毛玻璃与阴影，中间留 12px 间距；各自有独立滚动条。

**缝里不铺任何东西** —— 试过填一层同样的玻璃，会把两张卡焊成一根柱子，观感更差，已回退。
缝里露出的就是页面背景，靠三件事让它读起来干净：

1. 卡片有**玻璃边**（`--card-border`）→ 轮廓立起来
2. `--card-shadow` 足迹收一点（`0 10px 26px -12px`）→ 别让上下两张卡的投影在十几 px 的缝里叠两层
3. **浅色底整体抬亮** → 底色越接近卡片，缝越不像"脏印子"

**卡片不支持折叠**（曾经的"点标题栏收起"已整体移除）：折叠后分隔条没有高度可分配，会变成"拖了没反应"。
要缩小某张卡就拖分隔条（15%~80%），要不占地方就把它的内容清空/收起内部项。

上面那张卡的高度**就是**分隔条定的固定高度（`flex: 0 0 <split>%`），下面那张吃掉剩余，底边与主区卡片齐平。

### 三个把手：可见即悬停才浮出

| 把手 | 作用 | 量 |
| --- | --- | --- |
| 卡片顶部拖拽条 | 换位 | 13px → **9px**（收薄） |
| 两卡之间分隔条 | 调高度 | 上面那张卡的固定高度 15%~80% |
| 侧栏右边缘 | 调宽度 | 视觉落在"侧栏右 ↔ 主卡片左"缝的正中 |

三个把手的**可见部分都保持"悬停才浮出"**；为了让它们好抓，只有一个**完全不可见的命中区**被放大：
宽度手柄左右各溢出一截（`::before`，left `-8px` / right `-26px`，上下再各 `10px`）、
高度分隔条上下各撑 `6px`（`::before`）—— 观感一点不变，但不用再瞄准那 6px / 14px。

持久化键：`cardtree:panelOrder` / `cardtree:panelSplit` / `cardtree:sidebarWidth`。

**拖拽条换位**：鼠标移上去时**只在抓手周围浮出一颗小胶囊**（不再给整条 200px 的底色 —— 那看着像一行可点内容），
按住拖到另一张卡的上方/下方即换位；**标题栏也照样能拖**（卡片已不支持折叠，所以点击和拖动不冲突）。
拖动中有一个跟着鼠标的深色小药丸（写着卡片名），落点卡整张描边、那条边再画一条强调横线。

⚠️ 换位走的是**指针事件**（`mousedown`/`mousemove`/`mouseup`），**刻意不用原生 HTML5 拖拽**：
后者是否肯启动取决于浏览器环境，在扩展里会静默失败（连 `dragstart` 都不一定来），而且它对"落点在子元素上"极敏感。
指针事件完全可控，和「拖宽度」「拖分隔条」是同一套机制；拖动超过 **4px** 才算拖拽，松手后那一次 `click` 会被吞掉。

### 拖中间分隔条调高度：必须是固定高度

⚠️ 这里曾经用 `max-height`（高度**上限**）而不是固定高度 —— 后果是：工作区列表短于上限时，
拖分隔条**数据变了但像素不动**，用户只会觉得"拖不动"。已改为固定高度
（就是 Unity / PS 那种分栏：你定多少就是多少）。

> 回归见 `workspace-check` 的 `W13`（故意用**空工作区**去拖）。

上面那张卡内容少时会有空白，这是分栏布局的正常表现：把分隔条往上拖缩小它即可。
默认分栏比例 `0.4 → 0.33`（少留空白）。

### 拖拽投放态

一开始拖，整栏进入投放态（**两张卡都亮成投放区** + 顶栏文案变「移入文件夹」+ 「松手移入 N 项」提示条）；
悬停的文件夹行高亮为落点；拖文件夹到它自己/后代时整行变灰（`.drop-invalid`）并拒绝落点。

侧栏行的**悬停展开阈值从 600ms 收紧到 320ms**（行窄，等 600ms 手感发黏）。

**拖拽期间侧栏整棵树临时展开**（`store.dragExpandAll`）：否则悬停某行的自动展开会把下面的行推走，
你要投的那一行会在等待中漂移；拖完恢复各自的折叠状态。

**贴边唤出**：拖拽中把鼠标贴到窗口左边缘（≤12px）停 **200ms**，侧栏临时滑出；
真的用它投放了就留着，只是路过则还原你原本的设置（不偷偷改偏好）。

**hover 快捷动作**：悬停文件夹行时右侧浮出「＋（在此新建书签）」「⋯（重命名/移动/删除）」；
不占位、不改变行高（计数胶囊淡出而不塌陷），拖拽中自动让位回计数。

### 侧栏视觉打磨（一轮针对性的 UI pass）

- **面板内细滚动条**：全局把滚动条藏了（`::-webkit-scrollbar{display:none}`），面板内一溢出就
  **完全没有"还能滚"的提示**；现在单独给 `.panel-body` 恢复一条 7px 的细滚动条（`scrollbar-width: thin`）
- **文件夹层级树线**：原来只靠缩进区分层级，现在嵌套层左侧有一条淡竖线（末级子项用 `:last-child` 收在半高）
- **两卡列对齐**：chevron 列宽统一成 17px，工作区与文件夹的图标/文字列左右对齐；
  面板标题左内边距 = 行的 `padding-left`，标题与行首对齐
- **标题更清楚**：11px `--text-3` → 11.5px `--text-2`（之前淡到几乎看不见）；计数胶囊统一 10px，空计数更弱
- **空态从一行灰字改成引导卡**：虚线框 + 图标 + 说明 + 「＋ 新建工作区」按钮

## 看板索引条

视觉上和其他卡片用完全同一套配方，圆角 **9px**。之前它用的是 `--glass-bg-strong`（更白更实）+ 另一套阴影，
所以看着跟别的卡片不像一家人。

尺寸：工具条 `padding: 10px 12px`（高 51px）、胶囊 `padding: 5px 11px 5px 12px` / `12.5px`（高 29px）、
分组标签 `11.5px` + `--text-2`、计数徽标 `11px`。

**排版：标签换行后与胶囊左对齐。** 原来 label 和胶囊在同一个 flex 流里换行，第二行会缩到「标签」二字底下
（实测错开一个 label 宽度）；现在拆成 `.idx-group`（label | `.idx-chips`）两列，胶囊在自己那一列里换行 ——
实测两行首胶囊都在 x=327，完全对齐。

胶囊间距 `4 → 6px`（原来太挤）；计数徽标**定宽 19px + 居中**，同长度的标签胶囊宽度就一致了。
注：改成卡片配方（半透明 + 去掉白边）会让这条**看着比原来轻** —— 原来是 `--glass-bg-strong`
（近实白 0.72）+ 一道白边，像块实心白板；所以尺寸上补了一档。

胶囊的交互态和侧栏文件夹行保持同一套：hover = `--hover-bg` + `--hover-fg`，**不加描边/投影**
（原来用 `--chip-hover`，近乎实白，在玻璃卡里会糊出一块死白）；过渡统一 `0.2s`；
按下 = `--active-bg`（只改底色、不做位移）；选中态用 `--sel-bg` + `--focus-ring` 描边。

### 「最近浏览」放哪：放回卡片内

试过把它并进顶部看板索引条（两行 → 同一行），最终选择**放回卡片内部最上方**作为第一个分组：
索引条只负责"筛选/跳转"，最近浏览是"可以打开的内容"，两者语义不同，混在一条里反而不好读。
条目按**列**排（`grid` + `minmax(150px, 1fr)`，列数随卡片宽度自动）：实测窗口 1392 / 1092 / 892 时分别是 6 / 4 / 3 列。
只保留了两处改动：圆角 `8px→6px`（和顶部胶囊同一档）、hover 换成 `--row-hover` + 强调色文字。

## 工作区数据模型

条目存 `{ id, title, url }`，`title/url` 是**快照兜底**，渲染与打开优先用 `id` 取书签的**当前值**：

- **书签改名/改网址会跟着变**（以前只存快照、把 `n.id` 丢掉了，所以永远是旧标题）
- **书签被删则退回快照**并标「已删除」徽标，工作区不散架（这是当初存快照的初衷）
- 快照在每次 `load()` 后刷新，所以"改名后又删掉"显示的也是**最后知道的名字**，不是最初的旧名
- 老数据（只有快照没有 id）在启动时按 url 反查一次补上 id

**选中文件夹也能加进工作区**：递归收集里面的书签。以前只收 `n.url` 的节点、而 `topLevelSelection()`
又排除文件夹的后代 —— 选一个装着 8 个书签的文件夹会得到"没选中书签"。

**建组与"加入选中项"共用同一条去重逻辑**（原来建组不去重、加组才去重）。

**打开结果如实反馈**：全部失败 → "都没打开成功"；部分失败 → "打开了 M/N 个（K 个失败）"；只有真的开了才给「撤销」。

**零新增权限**：`chrome.tabs.create / remove` 属基础能力，不需要 `tabs` 权限（那权限是为了读 url/title
这类敏感字段）；非扩展环境回退 `window.open`。

**两种卡片的拖拽语义不同**：文件夹卡 = 移进去；工作区卡 = 加进清单（登记不是移动）。
两条路径共用 `store.addNodesToWorkspace()` 与同一套反馈文案。

## 其他踩坑

- **数据完整性**：`cdp-driver` 的 `T6` 断言 —— 拖拽/排序后若「其他书签 / 移动设备书签」的条目
  出现在书签栏，即判定失败（历史上曾因平铺数据被回写而导致真实书签被搬走）
- **首帧跳变**：注入 `chrome` 桩（storage 延迟 40ms），看刷新时宽度/主题是否跳变（`sidebar-firstpaint-check.mjs`）
- **版本号从 `chrome.runtime.getManifest()` 实时读**（`TopBar.vue`）—— 这是判断"扩展有没有重载"的唯一可靠信号
